zcat ../../data/At4.10.fa.gz | awk '
BEGIN {min=1e12; max=0; sum=0; len=0; n=0}
{
  if ($0 ~ /^>/) {
    if (len > 0) {
      if (len < min) min = len
      if (len > max) max = len
      sum += len
      n++
    }
    len = 0
  } else {
    len += length($0)
  }
}
END {
  # última secuencia
  if (len > 0) {
    if (len < min) min = len
    if (len > max) max = len
    sum += len
    n++
  }
  print "Secuencias:", n
  print "Longitud mínima:", min
  print "Longitud media:", sum/n
  print "Longitud máxima:", max
}'

¿Los parámetros corresponden al ensamblaje de un genoma haploide o diploide?

hifiasm está diseñado principalmente para genomas diploides. LO sabemos puesto que geera dos ensamblajes uno primario, p_ctg y uno alternativo o haploide, a_ctgque implementa la resolucion de los haplotips basandose en su heterocigosidad.

¿Qué nivel de eliminación de duplicaciones hemos aplicado? (El paso de eliminar duplicaciones sirve para que las zonas de alta heterocigosidad no sean ensambladas como contigs diferentes).

hifiasm aplica automáticamente una purga moderada estándar. Esta purga elimina duplicaciones debidas a heterocigosidad, pero sin ser extrema. ESte comportamiento esta controlados por parametros, como -l,que hace referencia a la longitudminima de la purga y -s sensibilidad para separacion de haplotipos. Sin embargo, se podrian modificar determinados parametros para hacer una purga mas o mnos radical.

#Evaluación del resultado

¿Dónde están las secuencias que componen el ensamblaje?

Las secuencias del ensamblaje están en los archivos .gfa, concretamente en las líneas de tipo S donde aparece: el identificador del contig y la secuencia nucleotídica

En los archivos .gfa, ¿qué son las líneas que empiezan por ‘A’?

Las líneas A contienen información de alineamiento de las lecturas que construyen cada contig/unitig. incluyen:

nombre del contig posición en el contig hebra (+/-) nombre de la lectura coordenadas de la lectura ID de la lectura estado de haplotipo

¿Qué información tiene los archivos .bed?

los archivos .bed (por ejemplo *lowQ.bed) contienen coordenadas de regiones de baja calidad en el ensamblaje, indican posiciones en los contigs y marcan zonas potencialmente problemáticas.
